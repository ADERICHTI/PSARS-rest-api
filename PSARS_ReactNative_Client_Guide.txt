================================================================================
PSARS COMPANION APP - REACT NATIVE CLIENT BUILD GUIDE
Personal Security & Anti-Kidnapping Response System
================================================================================

This document is a complete, standalone reference for building the React
Native companion mobile app that pairs with a PSARS hardware unit (ESP32 +
SIM800L) through the existing Firebase backend (project: psars-26) and
FastAPI telemetry service. It assumes nothing has been built yet on the
client side and covers everything: architecture, tooling, dependencies,
native configuration, folder structure, full source code, workflow/logic,
and known limitations.

================================================================================
SECTION 1: SYSTEM RECAP - WHAT ALREADY EXISTS (BACKEND)
================================================================================

Before touching the app, understand what it is talking to. This already
exists and is deployed:

1. FastAPI backend (P-SARS-API/main.py)
   - POST /api/v1/telemetry - hardware ingestion endpoint. Not called by the
     mobile app. The ESP32 posts here directly over cellular data.
   - On panic=true, it reads devices/{device_id}/emergency_contacts and
     sends an FCM push + Termii SMS to every contact found there.

2. Firestore (project: psars-26, database in europe-west1)
   Collections:

   devices/{device_id}
     - owner_user_id: string       (uid of the account that claimed this unit)
     - last_seen: Timestamp
     - latest_location: { latitude, longitude, panic, battery, timestamp }

   devices/{device_id}/locations/{locationId}
     - { latitude, longitude, panic, battery, timestamp }
     - Historical ping log, written only by the backend (admin SDK).

   devices/{device_id}/emergency_contacts/{contactId}
     - name: string
     - phone_number: string          (E.164 format, e.g. "2348012345678")
     - user_id: string | null        (set only if the contact has an account)
     - fcm_token: string | null      (set only if the contact has an account)
     This is what the app writes to when the device owner adds a contact.

   users/{user_id}
     - user_id, full_name, phone_number, fcm_token
     - device_id: string | null      (the ONE device this account owns/paired)

3. Firestore Security Rules (firestore.rules) - already deployed
   - devices/{deviceId}:
       create: allowed only if the document does not exist yet, and only
               if you are writing yourself as owner_user_id. This is the
               device "claim" - first account to claim a device_id wins,
               permanently, unless manually reset in the console.
       update: allowed only to the current owner_user_id.
       read: allowed to the owner, AND to any user with a matching
             emergency_contacts/{uid} record under that device (see below) -
             this is what lets a linked contact view the live map too.
   - devices/{deviceId}/emergency_contacts/{contactId}:
       read: the owner can read the whole list; a contact can read only
             their own record (by uid-as-doc-ID, or via a collectionGroup
             query matched on user_id) - this is how the app discovers
             "which devices am I a contact for."
       write: allowed only to the device's owner.
   - devices/{deviceId}/locations/{locationId}:
       read: same as the device doc - owner or linked contact.
       write: blocked entirely (backend-only, via the admin SDK which
              bypasses rules).
   - users/{userId}:
       read/write: allowed only to that same uid.

   HOW A CONTACT BECOMES "LINKED": their emergency_contacts document's ID
   must equal their own uid. contactsService.addContact() does this
   immediately when the contact already has an account at add-time. If they
   don't yet, the record starts under an auto-generated ID (SMS-only), and
   the backfillContactOnSignup Cloud Function re-keys it to their uid the
   moment they sign up (delete old ID, create at new uid-keyed ID) - at
   which point the read-access rule above starts passing for them
   automatically, with no app-side action required.

4. Cloud Functions (Cloud-functions/index.js, europe-west1) - already deployed
   - syncFcmTokenToContacts: when a user's own fcm_token changes, propagates
     the new value to every emergency_contacts record across all devices
     that references their user_id. The app never needs to do this itself -
     just keep users/{uid}.fcm_token current and this handles the rest.
   - backfillContactOnSignup: when a new user document is created, matches
     their phone_number against existing SMS-only contact records and
     upgrades those records with the new user_id + fcm_token automatically.

5. Firebase project reference
   - Project ID: psars-26
   - Firestore location: europe-west1
   - Functions region: europe-west1
   You will register the mobile app(s) (Android/iOS) under this same
   project in the Firebase console - see Section 4.

================================================================================
SECTION 2: HIGH-LEVEL APP RESPONSIBILITIES
================================================================================

The companion app has exactly these jobs:

  A. Authenticate the user (phone number based, since phone_number is the
     key used everywhere for contact matching).
  B. Maintain users/{uid} with full_name, phone_number, and a live fcm_token.
  C. Let the user "claim" a device by entering/scanning its device_id
     (writes devices/{device_id} with owner_user_id = uid).
  D. If the user owns a device: show its live location/status on a map,
     show battery, show a big panic banner when latest_location.panic is
     true, and show location history.
  E. If the user owns a device: manage its emergency_contacts subcollection
     (add/remove contacts by name + phone number).
  F. Receive and react to FCM push notifications (panic alerts) - whether
     the user owns a device or is only listed as someone else's contact.
  G. Let a user view the LIVE map of any device they're a linked emergency
     contact on - not just a static point from a push notification, but
     the same real-time Firestore feed the owner sees. Works from a
     dedicated "devices I'm watching" list, and from tapping a panic
     notification (which upgrades from a static pin to a live feed the
     instant Firestore responds).

SECTION 4: FIREBASE CONSOLE SETUP (DO THIS BEFORE WRITING CODE)
================================================================================

1. Open the Firebase console for project "psars-26".

2. Register an Android app:
   - Project settings -> Add app -> Android
   - Package name: com.psars.companion (use this exact value below, or pick
     your own and keep it consistent everywhere it appears in this guide)
   - Download google-services.json -> you'll place this at:
       android/app/google-services.json

3. (If building iOS) Register an iOS app:
   - Bundle ID: com.psars.companion
   - Download GoogleService-Info.plist -> place at:
       ios/PSARSCompanion/GoogleService-Info.plist

4. Enable Phone authentication:
   - Authentication -> Sign-in method -> Phone -> Enable
   - Android: Firebase Phone Auth needs SHA-1/SHA-256 fingerprints for
     Play Integrity verification (replaces the old SafetyNet flow).
     Get your debug fingerprint with:
       cd android && ./gradlew signingReport
     Copy the SHA-1 and SHA-256 under the "debug" variant into:
       Project settings -> Your Android app -> Add fingerprint
     You will need to repeat this with your RELEASE keystore's fingerprints
     before shipping a production build, or phone auth will fail silently
     in release builds.

5. Cloud Messaging:
   - No extra manual server-key setup needed for Android; FCM works out of
     the box once google-services.json is in place.
   - iOS requires an APNs Authentication Key uploaded under
     Project settings -> Cloud Messaging -> Apple app configuration, plus
     Push Notifications + Background Modes ("Remote notifications")
     capabilities enabled in Xcode. Push notifications do not work in the
     iOS Simulator - you need a physical device for FCM/APNs testing.

  import { auth, firestore } from './firebase';

  let confirmationResult = null;

  export async function sendOtp(phoneNumberE164) {
    confirmationResult = await auth().signInWithPhoneNumber(phoneNumberE164);
    return confirmationResult;
  }

  export async function confirmOtp(code) {
    if (!confirmationResult) {
      throw new Error('No OTP request in progress. Call sendOtp first.');
    }
    const userCredential = await confirmationResult.confirm(code);
    return userCredential.user;
  }

  export async function ensureUserDocument({ uid, phoneNumber }) {
    const ref = firestore().collection('users').doc(uid);
    const snap = await ref.get();
    if (!snap.exists) {
      await ref.set({
        user_id: uid,
        phone_number: phoneNumber,
        full_name: '',
        fcm_token: null,
        device_id: null,
      });
    }
    return ref;
  }

  export async function completeProfile(uid, fullName) {
    await firestore().collection('users').doc(uid).update({
      full_name: fullName,
    });
  }

  export function currentUser() {
    return auth().currentUser;
  }

  export function onAuthStateChanged(callback) {
    return auth().onAuthStateChanged(callback);
  }

  export async function signOut() {
    await auth().signOut();
  }

--- FILE: src/services/deviceService.js ---

  import { firestore } from './firebase';
  import firestoreNS from '@react-native-firebase/firestore';

  // Attempts to claim a device_id for the current user. Relies entirely on
  // firestore.rules to enforce "first claim wins" - if the device doc
  // already exists with a different owner_user_id, this create() call is
  // rejected by the server with a permission-denied error.
  export async function claimDevice(deviceId, uid) {
    const deviceRef = firestore().collection('devices').doc(deviceId);

    try {
      await deviceRef.create({
        owner_user_id: uid,
        last_seen: firestoreNS.FieldValue.serverTimestamp(),
        latest_location: null,
      });
    } catch (err) {
      if (err.code === 'firestore/already-exists') {
        throw new Error('This device is already registered.');
      }
      if (err.code === 'firestore/permission-denied') {
        throw new Error('This device is already connected to another account.');
      }
      throw err;
    }

    await firestore().collection('users').doc(uid).update({ device_id: deviceId });
    return deviceId;
  }

  export function listenToDevice(deviceId, onChange) {
    return firestore()
      .collection('devices')
      .doc(deviceId)
      .onSnapshot(
        (snap) => onChange(snap.exists ? snap.data() : null),
        (err) => console.warn('listenToDevice error:', err),
      );
  }

  export function listenToLocationHistory(deviceId, onChange, limit = 50) {
    return firestore()
      .collection('devices')
      .doc(deviceId)
      .collection('locations')
      .orderBy('timestamp', 'desc')
      .limit(limit)
      .onSnapshot(
        (snap) => onChange(snap.docs.map((d) => ({ id: d.id, ...d.data() }))),
        (err) => console.warn('listenToLocationHistory error:', err),
      );
  }

--- FILE: src/services/contactsService.js ---

  import { firestore } from './firebase';

  export function listenToContacts(deviceId, onChange) {
    return firestore()
      .collection('devices')
      .doc(deviceId)
      .collection('emergency_contacts')
      .onSnapshot(
        (snap) => onChange(snap.docs.map((d) => ({ id: d.id, ...d.data() }))),
        (err) => console.warn('listenToContacts error:', err),
      );
  }

  // If the contact already has an account, look them up by phone_number and
  // denormalize their user_id + fcm_token immediately. Otherwise store just
  // the name + phone_number - backfillContactOnSignup (Cloud Function) will
  // upgrade the record automatically if/when that number signs up later.
  export async function addContact(deviceId, { name, phoneNumber }) {
    const existing = await firestore()
      .collection('users')
      .where('phone_number', '==', phoneNumber)
      .limit(1)
      .get();

    const payload = { name, phone_number: phoneNumber };

    if (!existing.empty) {
      const userDoc = existing.docs[0];
      payload.user_id = userDoc.id;
      payload.fcm_token = userDoc.data().fcm_token || null;
    } else {
      payload.user_id = null;
      payload.fcm_token = null;
    }

    // Use the contact's own uid as the document ID when known - this is
    // what would let a future rules change grant that contact read access
    // to the device (see Section 16). When unknown, let Firestore
    // auto-generate an ID.
    const contactsRef = firestore()
      .collection('devices')
      .doc(deviceId)
      .collection('emergency_contacts');

    if (payload.user_id) {
      await contactsRef.doc(payload.user_id).set(payload);
    } else {
      await contactsRef.add(payload);
    }
  }

  export async function removeContact(deviceId, contactId) {
    await firestore()
      .collection('devices')
      .doc(deviceId)
      .collection('emergency_contacts')
      .doc(contactId)
      .delete();
  }

  // Devices the current user can view because they're listed as an
  // emergency contact on them (not because they own them). Works via a
  // collectionGroup query across every device's emergency_contacts
  // subcollection - firestore.indexes.json enables this query, and
  // firestore.rules only returns documents where this uid is the contact's
  // own record (owner-only contact records for OTHER people are filtered
  // out server-side, not just hidden client-side).
  export function listenToWatchedDevices(uid, onChange) {
    return firestore()
      .collectionGroup('emergency_contacts')
      .where('user_id', '==', uid)
      .onSnapshot(
        (snap) => {
          const devices = snap.docs.map((d) => ({
            deviceId: d.ref.parent.parent.id,
            contactId: d.id,
            ...d.data(),
          }));
          onChange(devices);
        },
        (err) => console.warn('listenToWatchedDevices error:', err),
      );
  }

--- FILE: src/services/notificationService.js ---

  import notifee, { AndroidImportance, AndroidCategory, EventType } from '@notifee/react-native';
  import { messaging, firestore } from './firebase';
  import { CONTACT_CHANNEL_ID } from '../config/constants';

  export async function setupNotificationChannel() {
    await notifee.createChannel({
      id: CONTACT_CHANNEL_ID,
      name: 'Panic Alerts',
      importance: AndroidImportance.HIGH,
      sound: 'default',
      vibration: true,
    });
  }

  export async function requestPermissionsAndRegisterToken(uid) {
    await notifee.requestPermission();
    const authStatus = await messaging().requestPermission();
    const enabled =
      authStatus === messaging.AuthorizationStatus.AUTHORIZED ||
      authStatus === messaging.AuthorizationStatus.PROVISIONAL;

    if (!enabled) return null;

    const token = await messaging().getToken();
    await firestore().collection('users').doc(uid).update({ fcm_token: token });

    // Keep Firestore in sync if the token ever rotates while the app is
    // open (reinstall, app data clear, etc). syncFcmTokenToContacts (Cloud
    // Function) then propagates this to every device's emergency_contacts
    // record that references this user - no client action needed there.
    messaging().onTokenRefresh(async (newToken) => {
      await firestore().collection('users').doc(uid).update({ fcm_token: newToken });
    });

    return token;
  }

  // Foreground messages: RNFirebase does not show a system notification by
  // itself while the app is in the foreground, so we display one manually
  // via notifee, styled as a high-priority panic alert.
  export function registerForegroundHandler(navigationRef) {
    return messaging().onMessage(async (remoteMessage) => {
      await displayPanicNotification(remoteMessage);
    });
  }

  async function displayPanicNotification(remoteMessage) {
    const { title, body } = remoteMessage.notification || {};
    const data = remoteMessage.data || {};

    await notifee.displayNotification({
      title: title || 'PSARS EMERGENCY ALERT',
      body: body || 'A panic alert was triggered.',
      data,
      android: {
        channelId: CONTACT_CHANNEL_ID,
        category: AndroidCategory.ALARM,
        importance: AndroidImportance.HIGH,
        pressAction: { id: 'default' },
      },
    });
  }

  // Handles the user tapping a notification (foreground via notifee, or
  // background/killed via RNFirebase) and routes them to AlertScreen with
  // the lat/lng/device_id payload.
  export function registerNotificationOpenHandlers(navigationRef) {
    notifee.onForegroundEvent(({ type, detail }) => {
      if (type === EventType.PRESS) {
        navigateToAlert(navigationRef, detail.notification?.data);
      }
    });

    messaging().onNotificationOpenedApp((remoteMessage) => {
      navigateToAlert(navigationRef, remoteMessage.data);
    });

    messaging()
      .getInitialNotification()
      .then((remoteMessage) => {
        if (remoteMessage) {
          navigateToAlert(navigationRef, remoteMessage.data);
        }
      });
  }

  function navigateToAlert(navigationRef, data) {
    if (!data || !navigationRef?.isReady()) return;
    navigationRef.navigate('Alert', {
      lat: parseFloat(data.lat),
      lng: parseFloat(data.lng),
      deviceId: data.device_id,
    });
  }

  import React, { useEffect, useRef, useState } from 'react';
  import { NavigationContainer, createNavigationContainerRef } from '@react-navigation/native';
  import { createNativeStackNavigator } from '@react-navigation/native-stack';

  import { onAuthStateChanged, currentUser } from '../services/authService';
  import { firestore } from '../services/firebase';

  import SplashScreen from '../screens/SplashScreen';
  import PhoneSignInScreen from '../screens/PhoneSignInScreen';
  import OtpVerificationScreen from '../screens/OtpVerificationScreen';
  import ProfileSetupScreen from '../screens/ProfileSetupScreen';
  import DevicePairingScreen from '../screens/DevicePairingScreen';
  import NoDeviceHomeScreen from '../screens/NoDeviceHomeScreen';
  import HomeDashboardScreen from '../screens/HomeDashboardScreen';
  import LocationHistoryScreen from '../screens/LocationHistoryScreen';
  import EmergencyContactsScreen from '../screens/EmergencyContactsScreen';
  import AddContactScreen from '../screens/AddContactScreen';
  import WatchedDevicesListScreen from '../screens/WatchedDevicesListScreen';
  import WatchedDeviceMapScreen from '../screens/WatchedDeviceMapScreen';
  import AlertScreen from '../screens/AlertScreen';
  import SettingsScreen from '../screens/SettingsScreen';

  export const navigationRef = createNavigationContainerRef();

  const Stack = createNativeStackNavigator();

  export default function RootNavigator() {
    const [booting, setBooting] = useState(true);
    const [user, setUser] = useState(null);
    const [profile, setProfile] = useState(null);

    useEffect(() => {
      const unsubAuth = onAuthStateChanged(async (u) => {
        setUser(u);
        if (!u) {
          setProfile(null);
          setBooting(false);
          return;
        }
        const unsubProfile = firestore()
          .collection('users')
          .doc(u.uid)
          .onSnapshot((snap) => {
            setProfile(snap.exists ? snap.data() : null);
            setBooting(false);
          });
        return unsubProfile;
      });
      return unsubAuth;
    }, []);

    if (booting) return <SplashScreen />;

    return (
      <NavigationContainer ref={navigationRef}>
        <Stack.Navigator screenOptions={{ headerShown: false }}>
          {!user ? (
            <>
              <Stack.Screen name="PhoneSignIn" component={PhoneSignInScreen} />
              <Stack.Screen name="OtpVerification" component={OtpVerificationScreen} />
            </>
          ) : !profile?.full_name ? (
            <Stack.Screen name="ProfileSetup" component={ProfileSetupScreen} />
          ) : !profile?.device_id ? (
            <>
              <Stack.Screen name="NoDeviceHome" component={NoDeviceHomeScreen} />
              <Stack.Screen name="DevicePairing" component={DevicePairingScreen} />
              <Stack.Screen name="Settings" component={SettingsScreen} />
            </>
          ) : (
            <>
              <Stack.Screen name="Home" component={HomeDashboardScreen} />
              <Stack.Screen name="LocationHistory" component={LocationHistoryScreen} />
              <Stack.Screen name="EmergencyContacts" component={EmergencyContactsScreen} />
              <Stack.Screen name="AddContact" component={AddContactScreen} />
              <Stack.Screen name="Settings" component={SettingsScreen} />
            </>
          )}
          {/* Reachable regardless of auth branch above: someone can own a
              device AND separately be a contact on someone else's, and a
              push notification can arrive no matter which branch is active. */}
          <Stack.Screen name="WatchedDevices" component={WatchedDevicesListScreen} />

--- FILE: src/screens/AlertScreen.js ---

  // Opened by tapping a panic push notification. Starts from the static
  // lat/lng the notification carried (so something renders instantly, even
  // before Firestore responds), then immediately upgrades to a LIVE feed by
  // subscribing to devices/{deviceId} - the same live map the owner sees,
  // available here because firestore.rules grants read access to any linked
  // emergency contact, not just the owner.

  import React, { useEffect, useState } from 'react';
  import { listenToDevice } from '../services/deviceService';
  import DeviceMapView from '../components/DeviceMapView';

  export default function AlertScreen({ route }) {
    const { lat, lng, deviceId } = route.params || {};

    const [device, setDevice] = useState({
      latest_location: { latitude: lat, longitude: lng, panic: true },
    });

    useEffect(() => {
      if (!deviceId) return;
      return listenToDevice(deviceId, (liveDevice) => {
        if (liveDevice) setDevice(liveDevice);
      });
    }, [deviceId]);

    return <DeviceMapView device={device} label="Live panic alert" />;
  }

SECTION 13: FULL END-TO-END WORKFLOW
================================================================================

1. User opens app for the first time.
   -> PhoneSignInScreen -> sendOtp() -> OtpVerificationScreen -> confirmOtp()
   -> ensureUserDocument() creates users/{uid} with device_id: null.

2. RootNavigator sees profile.full_name is empty -> ProfileSetupScreen.
   -> completeProfile() sets full_name.
   -> requestPermissionsAndRegisterToken() gets an FCM token and saves it
      to users/{uid}.fcm_token. From this point on, if this user is ever
      added as someone else's emergency contact by phone number, the
      backfillContactOnSignup Cloud Function upgrades that contact record
      automatically - the device owner does nothing.

3. RootNavigator sees profile.device_id is null -> DevicePairingScreen.
   -> User scans the QR code printed on their PSARS hardware unit (or
      types the device_id manually) -> claimDevice().
   -> claimDevice() calls .create() on devices/{deviceId}. Firestore rules
      allow this ONLY if no document exists yet at that path. If someone
      else already claimed it, the create is rejected with
      firestore/permission-denied, surfaced to the user as
      "This device is already connected to another account."
   -> On success, users/{uid}.device_id is set, flipping RootNavigator to
      the main app.

4. HomeDashboardScreen subscribes to devices/{deviceId} in real time.
   Every telemetry ping the ESP32 sends to the FastAPI backend updates
   latest_location here, which updates the map instantly. If panic is
   true, PanicBanner renders and (separately) every contact in
   emergency_contacts has already received a push/SMS from the backend at
   the same time this write happened.

5. EmergencyContactsScreen / AddContactScreen let the owner manage who
   gets alerted. Adding a contact with a phone number that already
   belongs to a PSARS account immediately links user_id + fcm_token; a
   contact without an account gets SMS-only until they sign up later
   (handled transparently by backfillContactOnSignup).

6. When a panic event fires on the backend, every contact with an
   fcm_token receives a push. Tapping it (app foreground, background, or
   killed - all three paths are wired in notificationService.js and
   index.js) opens AlertScreen, which shows the notification's lat/lng
   instantly and then upgrades to a LIVE Firestore feed of the device the
   moment it connects - the map keeps updating in real time for as long as
   the contact stays on that screen.

7. A linked contact doesn't have to wait for a panic push to check in.
   NoDeviceHomeScreen (if they don't own a device themselves) or
   HomeDashboardScreen's "Devices I'm watching" link (if they do) lists
   every device they're a contact on, via listenToWatchedDevices() - a
   collectionGroup query across all devices' emergency_contacts
   subcollections, filtered server-side by firestore.rules to only their
   own record. Tapping an entry opens WatchedDeviceMapScreen, the same
   live map, at any time - not just during an active alert.

SECTION 16: KNOWN LIMITATIONS / FUTURE WORK
================================================================================

1. Live contact viewing is now implemented (rules + backfill function
   deployed, RN screens in Section 12). One real edge case remains: this
   only re-keys emergency_contacts records going forward. If contacts were
   added to a device BEFORE this fix shipped, their record may still sit
   under an old auto-generated document ID even though user_id is already
   set - the isLinkedContact() rule check requires the doc ID itself to
   equal their uid, not just the user_id field, so a pre-existing record
   like that won't grant read access until it's re-keyed. A one-off
   migration script (query every emergency_contacts doc with a non-null
   user_id whose doc ID != user_id, and re-key it the same way
   backfillContactOnSignup does) would close this for any data that predates
   the fix - not needed for a fresh deployment, since every contact added
   from here on is keyed correctly at creation or at signup-backfill time.

2. One device per user. users/{uid}.device_id is a single field, so the
   current design does not support one account managing multiple PSARS
   units. If that's needed later, this becomes an array or a subcollection
   on the user doc instead, and DevicePairingScreen/HomeDashboardScreen
   need a device switcher.

3. Termii SMS still requires a sender ID to be registered and approved in
   the Termii dashboard for the `dnd` channel before real SMS delivery
   works - unrelated to the mobile app, but alerts will silently only
   arrive via push until that's done.

4. Phone Auth on Android release builds requires the release keystore's
   SHA-1/SHA-256 fingerprints added in the Firebase console (Section 4) -
   easy to forget and a common source of "works in debug, breaks in
   release" bugs.
